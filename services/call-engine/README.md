# call-engine

Scheduler, call flows and telephony for Tasalli reminder and consent calls.
Provider: **Twilio** (free trial) behind `TelephonyProvider`; `FakeProvider` for tests and local work.
Speech: Twilio `<Say>` (Hindi voice) for output and `<Gather input="dtmf speech" language="hi-IN">` for replies, so no separate TTS or STT service. `SpeechProvider` stays in the contract; the fake is used.

## Commands

```
pnpm --filter call-engine test        # 102 tests, FakeProvider and recorded Twilio payloads, no network
pnpm --filter call-engine lint        # tsc
pnpm --filter call-engine dev         # webhook server on PORT (default 8080); FakeProvider unless TELEPHONY_PROVIDER=twilio
pnpm --filter call-engine test-call +91XXXXXXXXXX   # one real consent-style call, see below
pnpm --filter call-engine test-reminder +91XXXXXXXXXX   # one real reminder call, 3 medicines, see "Reminder flow"
```

## Environment (names only; never commit values)

| Variable | Needed for |
| --- | --- |
| `TELEPHONY_PROVIDER=twilio` | use Twilio (otherwise FakeProvider) |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` | Twilio REST and signature check |
| `TWILIO_FROM_NUMBER` | caller ID (E.164), a number owned by your Twilio account |
| `CALL_ENGINE_PUBLIC_BASE_URL` (or `PUBLIC_BASE_URL`) | URL Twilio can reach, no trailing slash (the tunnel URL when local) |

| `TWILIO_RECORD=false` | turn call recording off (default: consent and reminder calls are recorded, mono) |

`pnpm dev` and `pnpm test-call` read the repo-root `.env` (variables already in the environment win).

## Reminder flow (v1.3: one medicine at a time)

A call for a dose group says the intro and the first medicine, then goes through the medicines in order. Per medicine:
"le li" / "haan" / 1 confirms only that dose ("Theek hai.", next medicine); "nahi" / "nahi li" / "baad mein" / 2 leaves it unconfirmed
("Koi baat nahi, thodi der mein phir yaad dilayenge.") and moves on; "phir se" / 0 repeats the same medicine in full;
unclear speech asks once ("... Le li ho to 1 dabaiye."), then keypad only, and a second miss or silence leaves it unconfirmed and moves on;
9 stops everything and blocks the number; 3 closes the unconfirmed doses and alerts the family. "No" is checked before "yes"; silence never confirms.
The call ends with "all taken" or "baaki dawai ke liye thodi der mein phir phone karenge".

- State: `session.reminder` (items, current index, per-dose outcomes, what was heard) lives in the session store, so a repeated webhook gets its stored reply and never advances twice.
- Confirmations are per dose (`Store.confirmDoses`). If any dose was "not now", one snooze (15 min) is queued for the group; if the snooze was already used, that dose is missed and the family is told. Doses nobody answered for use the normal 10-minute retries (2 more, then missed).
  Snooze and retry calls only cover doses still unconfirmed, so they may have fewer medicines (and the singular wording).
- Wording lives in `packages/scripts/{hi,en}.yaml` under `reminder_steps` (exported by `pnpm --filter @tasalli/scripts build:engine`). Placeholders: `{person_name} {child_name} {count} {time_of_day} {meal_relation} {ordinal} {spoken_name} {amount_text} {appearance_phrase} {pack_phrase} {disambiguator} {food_phrase} {extra_instruction}`. `{meal_relation}` is filled only when every medicine in the call has the same food rule.
- `test-reminder <E.164>`: same setup as test-call (root `.env`, throwaway server on `CALL_ENGINE_PORT`, MemoryStore). Creates "Papa" (child "Rahul", Hindi) with three medicines due now: "BP wali" (tablet, after breakfast), "sugar wali" (capsule, before food), "pet wali dawai" (syrup, after food), places one call (not recorded), and prints each medicine's outcome (confirmed / not taken / no answer) and the inputs heard. No retry or snooze calls are placed.

## Call recording (v1.2: recordings live in India)

Consent and reminder calls are created with `Record=true`, `RecordingChannels=mono` and a `RecordingStatusCallback` to
`<base>/webhooks/twilio/recording?c=<callId>` (signed like the other webhooks). Test calls are not recorded. Both consent scripts
say "This call may be recorded to improve the service." / the Hindi equivalent.

On `RecordingStatus=completed` the webhook enqueues a `recording.fetch` job (job id `recording_<RecordingSid>`, so a repeated webhook is a no-op; 8 attempts, exponential backoff). The job:

1. downloads the audio from Twilio (authenticated GET on `RecordingUrl` + `.mp3`; credentials only go to `api.twilio.com`),
2. saves it through `RecordingStorage` (`LocalFsRecordingStorage` under `RECORDINGS_DIR`, default `./.recordings`, key `<callId>/<RecordingSid>.mp3`) and checks the stored size equals the downloaded size (and the `Content-Length`),
3. writes our own path `/internal/recordings/<callId>/<RecordingSid>.mp3` to `calls.recording_url` (never a Twilio URL),
4. only then `DELETE`s the recording from Twilio (a 404 counts as already deleted).

Every step can be re-run; a failure throws and the queue retries. Nothing is deleted at Twilio before the local copy is saved and size-checked.
**Production:** implement `RecordingStorage` over object storage in the Mumbai region (for example S3 in ap-south-1); `LocalFsRecordingStorage` is for dev and a single-box pilot.
Deleting a person's data on request: remove the file named in `calls.recording_url`.

**Admin console access:** the call engine serves `GET /internal/recordings/<callId>/<RecordingSid>.mp3` only with `Authorization: Bearer $RECORDINGS_READ_TOKEN`
(constant-time compare; route is off while the variable is empty). The admin backend calls it server-side and streams the audio to the logged-in admin; the token never goes to a browser.

## Billing gate and evening summary

- Reminder calls (first call, retries, snooze) are skipped when the owner has no entitled subscription: `trialing`, `active`,
  `past_due` for at most 3 days counted from `subscriptions.past_due_since` (falls back to `current_period_end` only if that is null), or `cancelled` before `current_period_end`.
  Consent calls are not gated. Doses of a gated call group become `skipped_paused`.
- A skipped reminder emits one `plan_lapsed` alert per owner per local day (owner's time zone), job id `plan_lapsed_<userId>_<localDate>`, carrying the skipped person (the alert worker uses the nickname). Push and WhatsApp.
- At 20:00 in the parent's time zone the engine emits one `evening_summary` alert (`localDate`, job id `evening_summary_<personId>_<localDate>`) per person, for people who are consented, not paused and entitled.

## Try a real call locally (free tunnel)

1. Install cloudflared and start a quick tunnel to the port the engine will use:
   `cloudflared tunnel --url http://localhost:8080`
   It prints `https://<random>.trycloudflare.com`. The URL changes every run.
2. Export the environment (use your shell or a git-ignored `.env`):
   ```
   export TWILIO_ACCOUNT_SID=... TWILIO_AUTH_TOKEN=... TWILIO_FROM_NUMBER=+1...
   export PUBLIC_BASE_URL=https://<random>.trycloudflare.com
   ```
3. `pnpm --filter call-engine test-call +91XXXXXXXXXX`. It starts a throwaway webhook server on `PORT`,
   places a consent call through the real consent flow, and prints what happened (key pressed or words heard, consent result).
   Answer, then press 1 or say "haan"; 9 to test opt-out; say "nahi" to test the negative path.
4. For the full engine instead (`pnpm --filter call-engine dev` with `TELEPHONY_PROVIDER=twilio`), Twilio posts to
   `PUBLIC_BASE_URL/webhooks/twilio/status` and `/webhooks/twilio/input`. If the tunnel URL changes, restart with the new `PUBLIC_BASE_URL`
   (the URL is part of the signature Twilio computes; a mismatch gives 401).

## Twilio trial limits

- Calls only go to **verified numbers** (Console > Phone Numbers > Verified Caller IDs). Verify the founder's and any tester's phone first.
- The trial account has a **non-Indian caller ID** (a US/other Twilio number). The parent's phone shows that number; Indian numbers cannot be used as caller ID on trial. This is fine for testing, not for production.
- Trial calls begin with a Twilio message ("You have a trial account... press any key") before our script plays. Press any key to continue.
- Enable calls to India: Console > Voice > Settings > Geo permissions > India (off by default).
- Trial credit is limited; calls are short, and the 3 test calls/day cap per user applies to `test.call` jobs.
- Speech recognition on trial uses Twilio's default model; keys 1/2/0/3/9 always work as the fallback.
- Production later needs a paid account, Indian regulatory registration (TRAI/DLT, an Indian caller ID or a compliant route). Not in scope now.

## How it works

- `src/engine/scheduler.ts`: `schedule.replan` creates doses for the next 48 h in the parent's time zone and one delayed `dose.due` job per dose.
  When one fires, doses due within 30 minutes join one call group. Nothing is planned for people who are not `consented`, are paused, or whose number is blocked.
- `src/engine/calls.ts`: places consent, reminder and test calls. The 6/number/day cap (parent's local day, across accounts) and the block check run under a per-phone lock.
  Retries: 2 more calls, 10 minutes apart, then the doses are `missed` and a `dose_missed` alert is queued. Snooze once (15 min).
- `src/engine/flows.ts`: reply handling. Keys 1/2/0/3/9 and spoken replies; negative phrases first; unclear -> ask once -> keypad only -> goodbye; silence never confirms.
  Key 9 or a stop phrase (Hindi or English) blocks the number everywhere and opts out every person on it.
- `src/engine/engine.ts`: job dispatcher and `handleWebhook`: verifies the signature, records each event id once, serialises per call, replays the same reply for a repeated input, ignores terminal statuses after the call ended.
- Twilio: `src/providers/twilio.ts`. "Audio URLs" are `say:<lang>:<base64url text>`; the adapter turns them into `<Say>`. Webhook URLs carry `?c=<callId>&n=<nonce>`, so a retried request is the same event.
- Full flow tables and alerts consumed by other services: queue names and payloads are in `src/queue/jobs.ts`.

## Contract changes requested (not made here)

1. `TelephonyProvider.name` should include `'twilio'` (the adapter casts for now).
2. `renderNextAction(next, ctx?: { callId: string })`: optional second argument; Twilio needs the call id for the next webhook URL.
3. `CallEvent` speech: optional `confidence?: number` (Twilio returns it).
4. `packages/contracts/package.json`: `"type": "module"` so tsx can import its runtime values (`src/contracts-values.ts` is a synced copy until then).
5. `DoseStatus`: a `cancelled` value for doses removed by a schedule edit.
6. `CallEvent`: a `recording` event (`recordingSid`, `recordingUrl`, `status`); the engine handles Twilio's recording webhook outside `CallEvent` for now.
7. `subscriptions`: a `past_due_at timestamptz` column, so the 3-day grace period does not rely on `current_period_end`.
8. Alert kind `evening_summary` with `localDate` (already in `packages/integrations`).

## dose.remind

`dose.remind { doseId }` (from services/api, "send one more reminder"): one call for an upcoming (due within 30 minutes) or missed dose, no retries.
Confirmed or mid-call doses are ignored; a duplicate job places no second call; consent, block list, billing and the 6/day cap are re-checked.
